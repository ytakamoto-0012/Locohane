# git-commit-style

このプロジェクトのコミットメッセージ規約をまとめた「知識のみ」のスキルです。
実行するスクリプトはありません。以下の規約に従って文面を組み立ててください。

## 規約

1. **1行・日本語・簡潔に**書く（件名のみで完結させる）。
2. 先頭に変更種別を付ける（任意だが推奨）:
   - `追加:` 新機能・新ファイル
   - `修正:` バグ修正
   - `変更:` 既存挙動の変更
   - `整理:` リファクタリング・整形（挙動を変えない）
   - `文書:` ドキュメントのみの変更
3. 命令形ではなく、何をしたかを名詞・体言止めで簡潔に述べる。
4. 句点（。）は付けない。全角50文字以内を目安にする。
5. 機密情報（APIキー・パスワード等）を本文に書かない。

## 例

```
追加: スキル発見ミドルウェアと手書きReActグラフ
修正: run_scriptのタイムアウトが効かない不具合
整理: config読み込みをdataclassへ集約
文書: READMEにデータ保存場所と削除手順を追記
```

## 手順

1. ユーザーの変更内容を把握する（diff や説明から要点を1つに絞る）。
2. 上記の変更種別を1つ選ぶ。
3. 「種別: 要点」の形で1行にまとめて提示する。
4. 複数の無関係な変更が混在する場合は、コミットを分けるよう助言する。
