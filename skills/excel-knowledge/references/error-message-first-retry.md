# 再試行の前に、まずエラーメッセージそのものを読む

excel系スキル（`excel-edit`/`excel-read`/`excel-render`/`excel-recalc`）の
失敗ログに共通して見られたのは、**エラーメッセージに正解（あるいは正解への
手がかり）がそのまま書かれているのに、それを読まずに次の当てずっぽうへ
進んでしまう**パターン。個別の事例は[[read-render-args-and-queries]]・
[[edit-excel-invocation-contract]]にまとめたが、ここでは共通する考え方を示す。

## エラーメッセージの型ごとの読み方

- `未対応のqueryです: 'xxx'（対応op: [...]）` →
  対応op一覧がそのまま正解。次のopは一覧の中から選ぶ。一覧に無い機能は
  そもそも存在しないので、機能追加が必要ならユーザーに伝える。
- `usage: script.py [-h] ...` （`unrecognized arguments`）→
  `usage:`行がそのスクリプトの引数の**全て**。他スキルの引数体系を
  持ち込んでいないか確認する。
- `ops[N]（op='xxx'）の適用に失敗しました: <Pythonの例外詳細>` →
  何番目のどのopが、どんな例外で失敗したかが明示されている。
  N番目のopの引数（`sheet`名・`range`表記・型など）をその例外文言と
  照らして直す（例外文言自体がヒント。`KeyError`ならキー名の誤字、
  `ValueError`なら値の形式違反、等）。
- `one of the arguments --xxx --yyy is required` →
  そのコマンドは`--xxx`か`--yyy`のどちらかが**常に**必須。
  「今回はopsを使わない特殊な呼び出しのはず」という例外扱いを疑わない。

## 再試行するなら「エラー原因と変更点が対応しているか」を自問する

同一コマンドを、エラーとは無関係な引数だけ変えて再実行し、同じエラーで
再度失敗する事故が実際に起きている（`--overwrite`を追加しただけで
「ops必須」エラーを再現した例。[[edit-excel-invocation-contract]]参照）。
再試行の直前に、「今回変更した箇所」と「直前のエラーメッセージが指摘した
箇所」が一致しているかを確認する。一致していなければ、見た目を変えただけの
再試行であり、失敗が繰り返される可能性が高い。

## 2回連続で同じ種類のエラーになったら、read_skillで前提から確認し直す

当てずっぽうの微調整を3回目・4回目と繰り返す前に、一度`read_skill`で
該当スキルのSKILL.md（opsの一覧・引数の表・query節）を読み直す方が、
結果的に早く正解へたどり着く。実際のログでも、当てずっぽうを2回繰り返した
後にSKILL.mdを読み直して即座に解決した例がある。
