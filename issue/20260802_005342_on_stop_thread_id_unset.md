# on_stop 実行時に thread_id 未設定でWARNING（既知の想定内分岐）

- **区分**: 問題点
- **検知日時**: 2026-08-02 00:53:25
- **対象ログファイル**: data/logs/app_20260802_00_1.log

## 経緯

アプリ起動直後（`共有リソース初期化完了`から約2秒後、`on_chat_start`が
完了する前と見られるタイミング）に停止操作（`on_stop`）が実行され、
`cl.user_session` に `thread_id` がまだ設定されていない状態で
`on_stop` が呼ばれた。`app.py` 側は該当ケースを異常系として
コード中に明記した上で、何もせず早期returnする防御的分岐で処理して
いる（`app.py` L676-679のコメント参照）。

## ログ引用

```
2026-08-02 00:53:25,355 WARNING app.py: on_stop: thread_id が未設定のため何もしません
```

## 推定原因

`app.py` の `on_stop()` 内、`thread_id is None` 分岐
（コメント: 「`_setup()`/`on_chat_start` 完了前に停止が押された等の
異常系。紐づくセッションのグラフがまだ無いため何もしない。」）。
実装上は想定済みの防御的分岐であり実害は無いと見られるが、実際に
どの操作（起動直後のページリロード等）でこの状態に至ったかは
未検証。
