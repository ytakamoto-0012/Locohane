# サブエージェントがpath_memoryのディレクトリ用エイリアスに対しReadを繰り返し誤って呼び出す

- **区分**: 問題点
- **検知日時**: 2026-08-23 18:00:09
- **対象ログファイル**: data/logs/app_20260823_175334.log

## 経緯

explore サブエージェントが「子供会の過去実績をDatasフォルダから収集する」
タスク中、path_memory の `@11`（`E:\yukinori\ChatGpt-Prompt`。調査対象
Datasフォルダとは無関係な、探索初期のルート直下Globで割り当てられた
兄弟ディレクトリのエイリアス）に対して `Read` を実行し「指定パスは
ディレクトリです」エラーとなった（17:59:34）。その後も探索を続ける中で
`@126`（`E:\yukinori\テスト\Datas\2019`。これも深い階層探索で割り当てられた
ディレクトリのエイリアス）に対して同種の誤りが発生（17:59:40）。さらに
その後、**同一の `@11` に対して再度 `Read` を実行し、まったく同じエラーを
繰り返した**（18:00:09）。3回目のエラー直後にようやく `list_path_memory`
を呼び出して全エイリアス一覧（136件）を取得し、正しいファイル用エイリアス
へ切り替えて調査を継続。最終的には自力で回復している。

```
2026-08-23 17:59:40,214 WARNING src.subagent: subagent tool=Read args={'file_path': '@126'} -> エラー: 指定パスはディレクトリです（ファイル専用）: E:\yukinori\テスト\Datas\2019
```


## 推定原因

path_memory の `@N` エイリアスは、Globで見つかったファイル・ディレクトリの
両方に区別なく連番で割り当てられており、`Read` エラーメッセージ以外に
「そのエイリアスがファイルかディレクトリか」をLLMが事前に判別する手段が
無い。今回は探索初期（ルート直下Glob）で割り当てられた低番号の無関係な
兄弟ディレクトリのエイリアス（`@11`）と、後続の深い階層探索で新たに
割り当てられたディレクトリのエイリアス（`@126`）を、探索が長引き
コンテキストが肥大化する中でLLMが「ファイルのエイリアス」と誤認した。
特に `@11` は17:59:34と18:00:09の2回、**同一の誤りを繰り返しており**、
1回目のエラーメッセージだけでは「list_path_memoryを呼んで確認すべき」
という判断に至らず、無駄なツール呼び出し・LLM応答（このセッションでは
1回あたり数万トークン規模）を1回分余計に消費している。

改善案（未実装、今後の検討事項）:
- Read/Globのpath_memory参照エラーメッセージに「list_path_memoryで
  正しいエイリアスを確認してください」等の誘導文言を追加する。
- path_memoryの新規登録時・一覧取得時の返り値に、ファイル/ディレクトリの
  種別を明示する（既にlist_path_memoryの結果には含まれていないため、
  種別情報自体の追加も要検討）。
