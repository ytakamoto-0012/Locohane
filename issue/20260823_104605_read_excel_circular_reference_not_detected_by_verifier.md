# 循環参照（SUM範囲が自身のセルを含む）をverifierが機械的に検知できず見逃していた

- **区分**: 改善点 → 対応済み（ユーザー報告を受けて実装）
- **検知日時**: 2026-08-23 10:31:40〜10:46:08

- **対象ログファイル**: data/logs/app_20260823_102118.log

## 経緯

excel-vbaマクロブック作成タスクで、`cashflow.xlsm`の月別収支表シートに
`N8: =SUM(B8:N8)`・`N23: =SUM(B23:N23)`という数式が書き込まれた
（合計列N自身をSUM範囲に含めてしまっていた）。これはExcelが循環参照
エラーとして警告する内容。

10:31:40にファイル作成直後、`dispatch_agent(agent_type: verifier)`が
「データ: 各シートの見出し、項目、数式が正しく設定されているか」を含む
検証項目で呼ばれたが、この循環参照を**見逃した**（差異として報告されな
かった）。ユーザーが実際にExcelでファイルを開いて循環参照エラーに気づき、
「循環参照がありました。これがチェックで検出できていなかったようです」
と報告。

その後10:43台にメインエージェントが`execute_python_code_readonly`で
自力の数式レビューにより循環参照を発見・修正指示し、10:44:23の2回目の
`verifier`呼び出しでは明示的に「他に循環参照がないか確認」と指示された
ことで、`read_excel.py`が返す数式文字列を1件ずつ目視推論し正しく
判定できた（B25→C25→D25の連鎖は循環でない、N24=B8-B23は循環でない、
等の微妙な判定も含め正解）。

## 推定原因

`agents/verifier.md`のチェックリストに循環参照・数式の自己参照に関する
項目が存在せず、`read_excel.py`が返す既存の`warnings`機構（列幅超過等、
機械的に検知できる構造的不備をコード側で検知する仕組み）にも循環参照検知
が実装されていなかった。そのため1回目の検証では、明示的に指示されない限り
LLMが自発的に「各数式の参照範囲が自身を含んでいないか」を確認することは
なかった。

2回目の検証では明示的に依頼されたことで低パラメータモデルでも正しく
判定できたが、これは「毎回必ず聞かれる」保証が無い限り再発しうる（プロンプト
指示だけに頼る場合、依頼側が循環参照の可能性を疑っていなければ検証項目に
含まれず、今回の1回目のように見逃される）。列幅超過警告と同種の、機械的に
100%検知できる問題であり、コード側の`warnings`機構に載せるべき性質のもの
と判断した。

## 対応（実装済み・2026-08-23）

1. `skills/excel-read/scripts/read_excel.py`に`_formula_self_references()`を
   追加。数式文字列中のセル参照（シート修飾なしのもののみ、`Sheet2!A1`等は
   誤検知防止のため対象外）を正規表現で抽出し、参照範囲が自身の座標を
   含む場合を判定する。既存の列幅超過警告と同じループ内で、数式セル
   （`--data-only`未指定時のみ。指定時はキャッシュ値になるため自動的に
   スキップされ誤検知しない）についてこの判定を行い、`warnings`配列へ
   `'{シート名}!{セル}' の数式（...）が自身のセルを範囲に含んでおり、
   Excelで循環参照エラーになる可能性があります`という警告を追加する。
2. `skills/excel-read/SKILL.md`の`warnings`説明に循環参照警告の仕様を追記。
3. `agents/verifier.md`のExcel向けチェックリストに「数式の循環参照(xlsx)」
   項目を追加し、`warnings`の循環参照指摘を必ず確認するよう明記した。

テスト: `tests/test_excel_read_circular_reference_warning.py`を新規追加
（8件）: `_formula_self_references`の単体テスト（自己参照検知・非該当・
単一セル自己参照・連鎖参照の非該当判定・シート修飾参照の除外）と、
`_read_xlsx`統合テスト（循環参照ありで警告発生・正しい範囲で警告なし・
`--data-only`時は判定自体が働かないことの確認）。`pytest tests/`
420件全通過。
