# 会話履歴の自動要約に失敗（context_compaction）

- **区分**: バグ
- **検知日時**: 2026-08-02 10:40:12
- **対象ログファイル**: data/logs/app_20260802_10.log

## 経緯

トークン上限到達によりメインエージェントが引継ぎプロンプトを生成した直後、
`src.context_compaction` による会話履歴の自動要約処理が失敗した。
圧縮がスキップされたため、チェックポイント上のメッセージ数が
そのまま保持され続ける。

## ログ引用

```

```

## エラー原文

```
ERROR src.context_compaction: 会話履歴の自動要約に失敗しました。今回は圧縮をスキップします
```

## 推定原因

未検証。`context_compaction.py` 内の要約処理（LLMへの要約依頼）が
何らかの理由で失敗したものと推測される。具体的には:

- 直前のトークンガード発動でLLM応答が途切れた影響
- 要約プロンプトのコンテキストが超限界に達していた
- チェックポイントのメッセージ数が `min_messages_to_compact` を超えていない

`config.ini` の `[context_compaction]` セクションの設定:
- `token_threshold`: 49152
- `min_messages_to_compact`: 10
- `keep_recent_turns`: 2

## 追記（2026-08-22 23:21）

同一パターンで再発（excel-vbaマクロブック作成タスク中、長時間・大量ツール
呼び出しの会話）。今回もトレースバックまで確認できたため、既存の推定
「ループ検知→要約失敗」を裏付ける形で記録する。

```
2026-08-22 23:20:58,506〜23:21:05,743 DEBUG src.llm: ループ検知チェック: buffer_len=7432→8493, match_ratio=0.092→1.000, consecutive_hits=0→2
2026-08-22 23:21:05,743 WARNING src.llm: LLM応答のループを検知したため生成を打ち切ります
2026-08-22 23:21:05,744 ERROR src.context_compaction: 会話履歴の自動要約に失敗しました。今回は圧縮をスキップします
```

要約対象の会話履歴自体が長大な状態で「要約プロンプトへの応答」を生成する
LLM呼び出し中に、出力テキストが徐々に反復し始め（match_ratioが
0.092→0.283→0.537→0.787→1.000と単調増加）、最終的に完全一致（1.000）で
ループ確定・打ち切りとなった。要約対象の会話が既に肥大化しているタイミング
ほど、要約自体の生成もループしやすいという既存の推定と整合する。

`context_compaction.py:295`の`maybe_compact`は例外を握りつぶして
「今回はスキップ」するだけで、次回の圧縮試行タイミングで再度同じ理由で
失敗する可能性が高い（要約対象がさらに肥大化しているため）。ユーザーの
既存回答「様子見」を踏襲し、今回もコード修正は行わない。

`default_workdir`直下の絶対パスを渡して`run_script`が書き込みガードで

出るほど同じ対症療法的な書き直しが繰り返され、14:32:40には
`src.llm`のループ検知（LLM応答の反復）も1回発生した。これらの失敗の
やり取り自体がコンテキストを肥大化させ続け、要約対象がさらに長大化する
悪循環になっていたと考えられる。既存の推定「ループ検知・肥大化した
会話ほど要約自体も失敗しやすい」を裏付ける実例だが、今回は珍しく
膨張の一次要因（2つの書き込みガード関連バグ）まで特定できた。
根本対応は上記2issueのガード側修正であり、`context_compaction`自体への
対処は引き続き不要（ユーザー回答「様子見」を踏襲）。
